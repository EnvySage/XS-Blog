算法日记（二）：双指针同走、BFS 框架与二分边界

学习周期：2026.09.16 ～ 2026.09.18（Day 16 ～ Day 20）
使用语言：Python 3
内容：承接《算法日记（一）》，从"两棵树同步行走"讲到 BFS 层序遍历与二分查找

一、Day 16｜#572 另一棵树的子树：我以为我看懂了递归（2026-09-16）

今日题目

给你两棵树，判断 subRoot 是不是 root 的子树——所谓子树，是指 root 里存在某个节点，它带着自己下面整棵挂着的结构，和 subRoot 一模一样。

选它是因为它是 #100「相同的树」的直接复用：昨天我已经会判断"两棵树是否相同"了，今天只多一件事——在哪些位置调用这个判断。听起来简单，今天在这上面绕了整整一小时。

思路演进

第一反应：我写了个 if root == subRoot: return True，觉得理所当然——两个变量存的树一样，不就是相等吗？

被打回现实：Python 的 == 对 TreeNode 比的是"是不是同一个对象"，不是"长得像不像"。LeetCode 没给它定义 __eq__，所以两棵结构完全相同的树照样不相等。判结构，只能老老实实调用自己的 isSameTree。

or 那行在前，把"两个都空"顺手判成了 False，and 那行成为永远不执行的死代码。修法就是上下调换顺序：先认"都空 = True"，再认"一空 = False"。

然后我卡在了一个更根本的问题上：为什么两个 None 要返回 True？“它只确认了结构，没确认值啊？”

这个问题问得好，答案要画一棵树才讲得清。root 和 subRoot 都是 [1,2]：

关键在于：每个节点的值，是由"它自己被传进 isSameTree 的那一层"负责比掉的。往下递归传 None 时，那个位置本来就没有节点，没有任何数字等待被比较，问的只是"这片空地方和那片空地方一样吗"——当然一样。

反过来说，如果两个 None 返回 False，那每棵树的每个叶子都会因为"它的空孩子不相同"而失败，天下没有两棵树是相同的。递归总得有个地方交代"空树之间彼此相等"，这就是基准情形存在的理由。

踩坑记录

  1. root == subRoot 判不了两树相同：Python 默认比对象身份，TreeNode 无 __eq__。判结构必须显式调用比较函数。
  2. 基准情形顺序：or 写在 and 前面会截胡"都空"的情况，让 and 那行变成死代码。
  3. 漏查根节点自己：递归下探之前，当前节点首先是一个候选。
  4. 值相等 ≠ 子树相等：检查候选必须整座比，不能只比一个 val。
  5. 递归时把遍历写成了 isSameTree(root.left, ...)：往下找候选是 isSubtree 的活，isSameTree 只负责"从这一层往下整座比"。

知识点笔记

双递归的分工模式：一个函数负责"找候选"（遍历整棵树），一个函数负责"验结构"（同时下探两棵树）。前者对每个节点做三件事：验自己、去左边找、去右边找：

这种"两个指针同时往下走"的骨架，就是 #100、#101、#572 共用的那一副。

递归的心法：想清一层干什么 + 基准情形是什么，然后信任黑盒。别试图在脑子里展开整棵调用树，拿一棵两三个节点的小树手动 trace 就够验证逻辑了。

举一反三

  • #100 相同的树——本日的验证黑盒
  • #101 对称二叉树——同样两指针同走，只是走法镜像
  • #617 合并二叉树——下一题：两指针同走，从"判断"变"构造"
  • 链表版的同套路：判断回文链表也可以用"找 + 验"分工

一句话带走

遍历用 isSubtree，验证用 isSameTree；当前验一下，左右各找一遍。

二、Day 16（下）｜#617 合并二叉树：从"用 self 攒树"到"返回值就是交付物"

今日题目

给两棵二叉树，重叠位置的节点值相加，不重叠的位置直接把那边的子树搬过来，返回合并后的树。昨天预告过的题——#572 那副"两指针同时往下走"的骨架，今天从判断变构造。

思路演进

第一版我的思路对了一半：合并规则自己抓得很准（都在 → 相加，只有一边 → 拿那一边），但写法是：

两个错，一个比一个根本：

  1. 症状：root2 明明是 None 还写 root2.left——AttributeError。这不是新坑，是一小时前 #572 里刚踩过的，同一天左右手互搏。
  2. 病根：想用一个 self.resultTree 攒出整棵树。#543 的 self.maxDiameter 好用，因为它是个数字，各层往同一变量上刷最大值就行；但这里每层产的是一个节点，全局只有一个节点可以刷，父子层的产出全挤在一个点上互相覆盖。

真正的认知升级就一句话：树有多个节点，每个节点都得有人接住——构造类递归的交付通道是返回值，不是成员变量。每层 return node，上一层用 node.left = ... 接住，树在"返回 → 挂接"的链上自己长出来。

第二种写法是"直接改 root1"：不新建节点，root1.val += root2.val，结果写回旧树再返回。LeetCode 不要求保留原树，这版更省。当时给它们编号"模式一 / 模式二"，二十分钟后回想"模式二是什么"已经答不上来——刚讲的分类当场蒸发。（教训自查：不该起无语义编号，"造新树 / 改旧树"才是记得住的叫法。）

最后合上窗口凭记忆默写"改旧树"版，一次全对：

踩坑记录

  1. None 面前无属性（二犯）：递归进空子树前先看一眼你在对谁取 .left。#572 的守卫写法今天原样能救命：一边空就直接 return 另一边，连判断都不需要往下钻。
  2. self 攒树塌缩：成员变量适合"一个标量、各层取极值"，不适合"多个节点、逐个组装"。用错通道，树全被覆盖成一个点。
  3. 无语义编号记不住：“模式一 / 二"这种临时命名等于没命名，以后全用"造新树 / 改旧树”。

知识点笔记

递归的三种交付方式（到今天集齐了）：

产出 通道 例子
布尔判断 返回值 or / and 串联 #100 / #101 / #572
一个极值 self 成员边遍历边刷 #543
一棵新结构 返回值逐层挂接 #617

构造类递归模板：空手兜底（if not x: return y）→ 造 / 改当前节点 → 左右递归挂上 → return。

举一反三

  • 同骨架前置：#100 → #572 → #617，两指针同走，只是"当前层干什么"从比、到验、到造。
  • #226 翻转二叉树也是构造类，只是原地改，走的"改旧树"路线。

一句话带走

判断走返回值，极值走 self，建树——还是走返回值，一层接一层。

四、Day 17｜#102 二叉树的层序遍历：从 DFS 跨到 BFS（2026-09-17）

今日题目

给你一棵二叉树，返回每一层的节点值，按层从上到下。经典的 BFS 入门题，也是 Blind 75 必做。

思路演进

第一反应是硬套递归。前面做了 7 道树题全是递归 DFS，习惯性地写了 self.levelOrder(root.left) + self.levelOrder(root.right)，想让递归"自己返回每一层的结果"。写出来一堆 return stack.append()（append 返回 None，直接炸），nodeLeft + nodeRight 拿到的是 None + None → TypeError。不是代码写错了，是工具选错了——递归天然一路钻到底再回头，不擅长"一层一层平铺"。

卡点一：队列里存的是什么？ 这是最关键的认知跃迁。一开始以为队列里存的是"值"（数字），那 pop 出来之后队列就空了，怎么继续？答案是：队列里存的是整个节点对象。取出来一个节点，用 .left、.right 找到它的孩子，再 append 进去。pop 出来一个，append 进去可能零个、一个、两个——队列里的"人"换了，但不是空了。像排队买奶茶，你走了，你带的小孩排到队尾了。

卡点二：怎么知道这一层有几个节点？ 在开始处理某一层之前，len(queue) 恰好就是这一层的节点数。因为上一层处理完后，只有上一层的节点才会往队列里加孩子——这些新加的孩子，正好就是下一层的全部。先记长度，再按这个数量循环取，取完刚好处理完一层。

关键代码

踩坑记录

  1. return stack.append()——append 返回 None，别拿 append 当返回值。
  2. 以为队列存的是值 → pop 之后就空了。实际上存的是节点对象，才能用 .left / .right 继续探路。
  3. 一开始想用递归做 BFS，工具选错了。递归 = DFS，BFS 需要队列。

知识点笔记

DFS vs BFS 对比：

DFS（递归 / 栈） BFS（队列）
工具 递归调用栈 deque 队列
走法 一路钻到底再回头 一层扫完再下一层
适用场景 深度、路径、回溯 层级、最短距离

BFS 框架（一句话）：队列存节点，while 循环，每轮先记长度再按长度取，取的时候把孩子丢进去。

队列 vs 列表：Python 的 deque 出队 O(1)，list.pop(0) 是 O(n)，做 BFS 永远用 deque。

举一反三

  • 这个 BFS 框架是所有层序遍历变体的基础（锯齿形、右视图、最大层宽）——改的只是 for 循环里面做什么
  • 下一步可以做 #199 二叉树的右视图（BFS 取每层最后一个）

一句话带走

队列存节点，先问 len 再按数取，pop 一个 append 孩子，层就换了一波。

五、Day 18｜#111 二叉树的最小深度（2026-09-17）

今日题目

给一棵二叉树，返回最小深度——从根到最近叶子的最短路径上的节点数。和 #102 层序遍历同一天做，是 BFS 框架的第一个变体。

思路演进

框架直接搬 #102。 队列存节点，按层展开，每层 len(queue) 定长度。唯一区别：不收集所有层的值，而是找到第一个叶子就 return。BFS 天然按距离从近到远展开，第一个碰到的叶子一定是最浅的。

代码一次通过，零修改。核心就一行判断：if not node.left and not node.right: return result。

踩坑记录

无。BFS 框架熟练后，这类变体就是改 for 循环里的判断条件。

知识点笔记

  • BFS 的优势：天然最短路径。需要"最近"“最小深度”"最短距离"类答案时，BFS 一找就是最优。
  • 提前 return：不需要遍历整棵树，找到目标立刻收工。#102 要遍历完，#111 找到就跑。

举一反三

  • #102 层序遍历 → #111 最小深度（加 early return）→ #199 右视图（取每层最后一个）
  • #637 各层平均值（BFS + 求平均）

一句话带走

BFS 从近到远展开，找最近的叶子，找到就跑。

六、Day 19｜#199 二叉树的右视图（2026-09-18）

今日题目

从右边看一棵二叉树，返回你能看到的节点值。本质是 #102 的变体：每层只取最右边那个。

思路演进

框架完全搬 #102，只改了 for 循环里收集的逻辑：不存整层，直接 level[-1] 拿最后一个。代码一次通过。

当时的点评很精准：“完全就是把 102 的数据再处理一下”——对，这就是框架的价值：骨架不变，换零件。

知识点笔记

七、Day 20｜#704 二分查找：第一次碰边界条件（2026-09-18）

今日题目

有序数组里找一个数，返回索引；没找到返回 -1。O(log n) 时间，二分查找的入门题。

思路演进

第一版写法完全跑偏。 没有维护 l 和 r 两个边界，而是试图直接算出新 index。边界从头到尾没动过，导致 target 不在数组时 index 在某个值上来回跳 → 死循环。另外用了 / 浮点除法，index 变成 1.5 这种小数当列表下标直接 TypeError。还有一个永远走不到的 else: return -1（==、>、< 已经覆盖所有情况）。

核心纠偏：二分不是"算新位置"，而是"砍边界"。 每次比较后，要么 r = m - 1（右边界左移），要么 l = m + 1（左边界右移）。搜索范围每次砍一半，所以是 O(log n)。

默写一次通过。 理解了"动边界再算中间值"的逻辑后，标准模板就写出来了。

踩坑记录

  1. 边界不动 = 死循环：l 和 r 必须在比较后更新，不然搜索范围永远不变。
  2. Python 3 的 / 是浮点除法：整数除法用 //，否则 index 变 float，列表下标报 TypeError。
  3. else: return -1 是死代码：== / > / < 三路已经全覆盖，不需要 else。

关键代码

知识点笔记

为什么用 l <= r 而不是 l < r？

  • l <= r：区间 [l, r] 还有元素就继续，l 和 r 重合时那个位置也要查
  • l < r：区间只剩一个元素时跳过，需要额外处理

边界更新为什么要 m - 1 / m + 1？

  • nums[m] != target 已经确认 m 不是答案
  • 不把 m 排除掉的话，搜索范围不缩小 → 死循环

整数除法防溢出（了解即可）：

  • (l + r) // 2 在 l 和 r 都很大时可能溢出（Python 不怕，但 Java / C++ 要注意）
  • 安全写法：l + (r - l) // 2

举一反三

  • #704 是基础模板，后续变体：#35 搜索插入位置、#34 查找左右边界、#33 搜索旋转排序数组
  • 共同骨架：维护 l / r，循环里算 m，按比较结果砍边界

一句话带走

二分的核心是砍边界，不是算位置。动 l 或 r，再取中间值。

八、系列小结

Day 16 ～ 20 的关键词是框架：

  • 递归的三种交付方式（返回值 / self / 返回值挂接）——什么时候用哪个，这几天才真正分清
  • 两指针同走：同一副骨架，当前层从"比"到"验"到"造"
  • BFS：队列存节点、先记 len 再按数取；变体只换 for 循环里的零件
  • 二分：核心是砍边界，不是算位置

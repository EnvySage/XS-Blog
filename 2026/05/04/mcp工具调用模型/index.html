基于 LangGraph + MCP 构建 12306 车票查询 Agent —— 从基础调用到人工审核拦截

本文记录了如何使用 LangGraph 状态图编排 + MCP（Model Context Protocol） 协议接入外部工具，构建一个具备 Human-in-the-Loop（人工审核） 能力的 12306 车票查询 Agent。我们将从最基础的工具调用开始，逐步演进到带人工审核拦截的生产级方案。

项目背景

在构建 AI Agent 时，我们经常需要让大模型调用外部工具（如查数据库、调 API）。MCP（Model Context Protocol） 是 Anthropic 提出的一种标准化协议，让 LLM 能够以统一的方式接入各种外部工具服务。

本项目以 12306 火车票查询 为场景，演示了：

文件 作用
mcp_util.py MCP 客户端配置与异步工具节点
graph.py 基础版：LangGraph 调用 MCP 工具
graph2.py 进阶版：加入人工审核拦截 + Token 消耗统计

LLM 使用的是阿里云通义千问 qwen3-max 模型。

核心架构概览

整个 Agent 的运行流程可以用一张状态图来描述：

  • chatbot 节点：调用 LLM，判断是否需要使用工具
  • tools 节点：执行 MCP 工具，可选地进行人工审核拦截
  • 条件边：根据 LLM 返回是否有 tool_calls 决定下一步走向

一、MCP 工具层 —— mcp_util.py

这是整个项目的基础设施层，负责 连接 MCP 工具服务 和 异步执行工具调用。

1.1 MCP 客户端配置

说明：MultiServerMCPClient 支持同时接入多个 MCP 服务端，通过字典的形式注册。每个服务使用 SSE（Server-Sent Events） 协议通信，这是一种轻量级的单向实时通信方式，适合 MCP 这种请求-响应场景。

调用 mcp_client.get_tools() 即可获取所有已注册服务提供的工具列表，返回的工具对象与 LangChain 的 Tool 接口完全兼容，可以直接用 llm.bind_tools(tools) 绑定给大模型。

1.2 异步工具节点 BasicToolsNode

这是整个项目最核心的类之一，替代了 LangGraph 内置的 ToolNode，提供了更灵活的控制能力：

为什么不直接用内置的 ToolNode？

LangGraph 自带的 ToolNode 会无条件执行所有工具调用。但在实际生产中，我们可能需要对某些敏感操作（如查询车票、下单等）进行 人工审核。自定义 BasicToolsNode 让我们可以在工具执行前插入任意拦截逻辑。

1.3 并发工具调用

关键设计点：

设计 说明
asyncio.gather 所有工具并发执行，而非串行，显著降低总耗时
同步/异步自适应 通过 hasattr 检测 ainvoke 方法，对同步工具用 run_in_executor 包裹，保证不阻塞事件循环
ToolMessage 封装 每个工具调用结果封装为标准的 ToolMessage，携带 tool_call_id 以便 LLM 关联请求与响应

二、基础版 —— graph.py（纯工具调用）

这是学习阶段的基础实现，展示了 LangGraph 接入 MCP 工具的最小完整流程。

2.1 定义状态与条件路由

MessagesState 是 LangGraph 内置的状态类，默认包含一个 messages 字段（Annotated[list, add_messages]），自动管理消息的追加。我们继承它并直接使用，无需额外定义字段。

2.2 条件路由函数

这个函数在 chatbot 节点执行后被调用，决定下一步走向：

  • 如果 LLM 返回了 tool_calls（即决定调用工具），则路由到 tools 节点
  • 否则直接结束（END）

LangGraph 也提供了内置的 tools_condition 函数（from langgraph.prebuilt import tools_condition），功能相同。这里手动实现是为了更清晰地理解路由机制。

2.3 构建图

图的边连接逻辑：

tools 执行完毕后回到 chatbot，让 LLM 根据工具结果继续生成回复或发起新的工具调用，形成 工具调用的循环链。

2.4 执行方式

基础版在模块加载时即创建图实例，适合简单的单次调用或调试场景。

三、进阶版 —— graph2.py（人工审核 + Token 统计）

进阶版在基础版之上增加了两个重要能力：

  1. Human-in-the-Loop：对敏感工具调用进行人工审核拦截
  2. Token 用量统计：实时追踪每次 LLM 调用的 Token 消耗

3.1 人工审核机制

原理：interrupt + Command + checkpointer

LangGraph 提供了 interrupt() 函数，它可以让图的执行在任意节点中 暂停，等待外部输入后恢复。这是实现 Human-in-the-Loop 的核心机制。

要使用 interrupt，必须同时配置 checkpointer（检查点），因为暂停时需要保存当前状态，恢复时需要从检查点加载。

流程图：

注意：当用户拒绝时，必须返回一个 ToolMessage，并且其 tool_call_id 必须与被拒绝的工具调用 ID 匹配。否则 LLM 会因为收不到对应工具的响应而进入错误状态。

恢复执行的逻辑

关键点解析：

  • graph.get_state(config) —— 获取当前图的执行状态。current_state.next 不为空说明图被 interrupt 暂停了
  • Command(resume={'answer': user_input}) —— 构造恢复命令，将用户输入作为 resume 值传回 interrupt() 的返回值
  • stream_mode='values' —— 流式输出，每次返回完整的状态快照（而非增量更新）

3.3 交互式主循环

thread_id 是 LangGraph 检查点的唯一标识，相同 thread_id 的对话会共享记忆。这使得多轮对话中 interrupt 暂停和恢复的上下文得以保持。

踩坑记录

在开发过程中遇到了几个值得记录的问题：

1. UnboundLocalError: cannot access local variable 'result'

原因：execute_graph 函数中，result 在 if current_state.next 的分支内被赋值，但在 else 分支中未被初始化。当走 else 分支时，后续代码引用 result 会报错。

解决：在函数开头初始化 result = ''。

2. 工具拦截未触发 —— 工具名不匹配

原因：MCP 注册的工具名是 get-tickets（连字符），但代码中硬编码的是 get_tickets（下划线），字符串比较永远为 False。

解决：将比较字符串改为 'get-tickets'。更好的做法是配置一个需要审核的工具名列表，而非硬编码。

3. TypeError: Cannot instantiate typing.Union —— Command 导入错误

原因：Command 被错误地从 langchain_protocol 导入，该包的 Command 类型定义与 LangGraph 不兼容。

解决：使用 from langgraph.types import Command，与 interrupt 保持同一导入来源。

4. 拒绝工具调用后 LLM 进入异常状态

原因：拒绝时返回的 ToolMessage 没有携带正确的 tool_call_id，LLM 无法将响应对应到原始工具调用。

总结

能力 graph.py graph2.py
MCP 工具调用 ✅ ✅
异步并发工具执行 ✅ ✅
人工审核拦截 ❌ ✅
对话记忆（checkpointer） ❌ ✅
Token 用量统计 ❌ ✅
交互式多轮对话 ❌ ✅

从 graph.py 到 graph2.py 的升级过程，本质上是从 “让 AI 自由使用工具” 到 “在关键节点引入人类判断” 的演进。interrupt + Command + checkpointer 三件套是 LangGraph 实现 Human-in-the-Loop 的标准模式，掌握这套机制后，可以灵活地控制 Agent 的行为边界。

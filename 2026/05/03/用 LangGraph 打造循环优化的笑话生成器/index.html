用 LangGraph 打造循环优化的笑话生成器

学习日期：2026年5月2日
使用模型：通义千问 (Qwen3-Max)
参考资料：LangGraph 官方文档

最近在学习 LangGraph，写了一个有趣的小项目——让大模型不断生成笑话，直到满意为止。这背后用到了 LangGraph 的条件循环机制，非常适合"生成→评估→不满意就重来"的场景。

本文就来梳理一下其中的核心知识点。

先看效果

用户输入一个主题（比如"程序员"），系统会不断生成笑话，直到评估分数达到 3 分以上才会输出结果。

核心代码解析

1. 状态定义：TypedDict

LangGraph 中的状态（State）就像一个共享的黑板，所有节点都可以读写。TypedDict 声明了每个字段的类型，让代码更清晰。

关键点：节点函数返回字典时，只会更新对应字段，其他字段保持不变。比如返回 {"joke": "xxx"} 就只更新笑话内容，不会影响 feedback 和 funny_level。

2. 链式调用：管道符 |

StrOutputParser() 的作用是提取 AIMessage.content，把对象转成普通字符串。

3. 结构化输出：with_structured_output

有时候我们希望 LLM 返回特定格式的数据，而不是自由文本。这时候可以用 Pydantic 模型配合 with_structured_output：

Field 中的 description 非常重要，它告诉 LLM 这个字段的含义。写得越详细，LLM 理解得越准确。

4. 图构建：StateGraph

StateGraph 是 LangGraph 的核心，通过三个方法构建整个工作流：

方法 作用
add_node(name, func) 添加节点，name 是唯一标识
add_edge(from, to) 固定边，上游完成自动执行下游
add_conditional_edges() 条件边，由函数返回值决定下一步

小结

这篇文章通过一个"笑话生成器"的例子，介绍了 LangGraph 的几个核心概念：

  • 状态共享：用 TypedDict 定义全局状态
  • 链式调用：用 | 串联 LLM 和输出解析器
  • 结构化输出：with_structured_output + Pydantic
  • 条件循环：add_conditional_edges 实现"不满意就重来"

这种模式不只适用于笑话生成，像文案撰写、代码优化、翻译润色等需要迭代改进的场景都可以用。LangGraph 让这类工作流的实现变得非常直观。

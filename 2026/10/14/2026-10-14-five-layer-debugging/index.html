一个「喵~」引出五层认知修正：LangGraph 状态与提示词的边界

学习日期：2026年10月14日
项目：deepsearch（从零重建 open_deep_research）
环境：Python 3.11 / LangGraph 1.x

起因

我在 agent 节点的 system prompt 里加了一句：

回答结尾加上「喵~」。

模型不照做。

单独把那句 prompt 拿出来测，同一个问题跑 3 次，3/3 都加了「喵~」。模型没问题。

那就只能是链路的问题。追了一整天，挖出五层，每层都比上一层更根本。

第一层：指令挂错了节点

最终回答不是 agent 产出的，是 write_report 节点产出的。

那是另一间办公室。它从零重构了上下文，压根看不到 agent 的 prompt。

修正：系统提示词不是“全局设置”，是“单次调用的参数”。

LangGraph 里没有“整张图的 system prompt”这种东西。节点之间只共享 state，不共享 prompt。

跨节点的要求必须做两步，缺一不可：

  1. 运输：把要求作为 state 的一栏摆上白板
  2. 消费：目标节点主动读这栏，写进自己的 prompt

只有①没有②，等于没写。

第二层：state 是白板，不是历史

我原来的理解：state 像“过去的状态记录”，是一条流水账。

修正：state 是一块共享白板。

  • messages 那栏用 Annotated[list, operator.add] → 追加，所以看起来像流水账
  • 但那是一栏的合并规则，不是 state 的本质
  • 另一栏 question: str 就是一直贴在白板上的便签，谁进门都能读

一句话：

指令跟着节点走（局部生效）；要求跟着 state 走（谁需要谁读）。

第三层：system 一个字都没到模型

换了中间代理后，system prompt 完全失效。挖出两层根因。

怎么证明的：两个探针

  • 行为探针：system 里写“必须以「菠萝蜜多」开头” → 0/4 遵守
  • 不依赖模型行为的探针：往 system 塞 900 字符，看 prompt_tokens 涨不涨 → 58 → 58，一个 token 都没涨

第二个探针是关键。它不依赖“模型表现”，直接看“内容有没有到”。

根因

那个代理默认会用自有提示词“替换”客户端的 system 消息。

失败方式全是“不报错、但也不干活”。

顺带发现：ToolMessage 的配对契约

ToolMessage 必须紧跟一条带 tool_calls 的 AIMessage，tool_call_id 要对上。

  • 保留 AI + Tool 配对 → 工具调用示范还在 → 模型会模仿
  • 只留 Tool、丢掉 AI → 变成孤儿 → 内容被静默丢弃

两条路都不通。唯一出路是：把工具正文降级成纯文本，重包成一条 HumanMessage。

还有一个环境坑

load_dotenv() 默认不覆盖已存在的环境变量。我机器上 ANTHROPIC_API_KEY 已被设成空字符串，把 .env 里的真 key 挡掉了，认证一直失败。

解法：load_dotenv(override=True)。

第四层：BaseModel 是数据模具，不是执行体

我原来的理解：class Plan(BaseModel) 是“定义模型的执行体”。

修正：它不执行任何东西。它只是一份能编译成 JSON Schema 的规格书。

TypedDict 和 BaseModel 的分工：

TypedDict BaseModel
传错类型 静默通过 强行转换或报错
少字段 取用时才 KeyError 构造即报错
用途 描述 state 形状 接模型输出、保证下游数据形状

一句话：TypedDict 是标注，BaseModel 是契约。

第五层：结构化输出会静默失败

with_structured_output(Plan) 不是万能的。

实测撞到：模型把整个数组序列化成了一个字符串（'["a","b"]'），parsed 返回 None。而代码里直接 plan.topics → AttributeError。

修法：吃结构化输出的地方必须判空。

它把成功率从 1/3 拉高到接近 100%，但不是 100%。

v0.3 的成果：子图 + 并行

这一天的最后，v0.3 跑通了：

  • supervisor 用结构化输出拆题
  • researcher 是独立子图
  • 多个研究员用 Send 并行派发
  • 最后汇总成一份报告
版本 耗时
串行（3 路） 114s
并行（3 路） 快了很多

日志证据：串行时打印整齐（1→2→3）；并行时三个研究员的轮次交错。这个“乱”本身就是并行在跑的证明。

今天最值钱的三条

  1. 系统提示词不是全局的，是“单次调用的参数”。 跨节点必须走 state。
  2. 验证要用不依赖输出的探针。 “内容有没有到”看 token 数，别看着像不像。
  3. 每一层都可能静默改你的请求。 不报错 ≠ 没发生。

被推翻的想法

  1. “模型不听话” → 指令挂错了节点
  2. “state 是历史记录” → state 是白板
  3. “代理返回什么模型就收到什么” → 中间层会静默替换 system
  4. “BaseModel 是执行体” → 它是数据模具
  5. “结构化输出一定成功” → 它会静默返回 None
